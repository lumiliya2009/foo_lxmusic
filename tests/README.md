## 播放错误与取消

```powershell
./run-input-regression.ps1 -Platform Win32
./run-input-regression.ps1 -Platform x64
```

脚本使用实际的 `input_lxmusic.cpp` 和 `media_stream.cpp`，仅替换 foobar2000 主线程、取消令牌、文件接口、音源和解码器边界。每种架构运行 21 项播放用例，覆盖解析失败、空地址、打开失败、初始化失败、播放失败、定位失败、取消后旧回调、非播放用途、正常结束和集合误播放。

另有 41 项音频流用例，覆盖 FLAC 被误标为 Ogg、Ogg/WAV/RF64/MP4 的类型更正、保留未知内容的原类型、短文件、逐字节读取、不可定位流、重新打开后的字节完整性，以及实际输入类是否将更正后的流传给解码器。ID3 标签不会被直接认定为 MP3，避免误伤其他使用 ID3 的格式。

验证失败解码在主线程停止之前不会返回可触发跳曲的错误，停止后能退出，提示包含歌曲与原因；用户已经取消时，旧回调不能再次停止播放或显示提示。这些测试模拟 SDK 的线程契约，不能代替实际宿主验证。

2026-11-19（0.1.4）：Win32、x64 各 62 项通过；两个安装包的架构、依赖和 DLL 与构建结果一致。构建仍有工程已有的 SDK 重复符号链接警告。

回归样本包含媒体服务器返回 `Content-Type: audio/x-ogg`，实际文件头却为 `66 4C 61 43`（`fLaC`）的情况。测试使用合成字节和临时文件，不需要音源订阅或私人播放列表。

## 实际宿主界面

```powershell
./prepare-host.ps1 -Platform Win32
./prepare-host.ps1 -Platform x64
```

脚本在 `build/test-host-*` 中创建独立的便携测试副本，使用本机已有的 foobar2000 和确定性测试桥接程序。不要将测试桥接程序用于正式安装包。

运行输出路径中的播放器，在“文件 → LX 在线音乐 → 搜索在线音乐”进行验证：

1. 搜索类型选专辑，结果首项应被选中并获得列表焦点。按回车应只打开当前项，双击也应打开。歌手、歌单结果行为相同。
2. 打开后选中“播放失败测试”并回车，应该停止并提示原因。测试组件目录中的 `requests.log` 不应出现 `resolve` 请求目标 `*-sentinel`，后者代表不应自动跳播的下一首。
3. 在测试组件目录将 `mode.txt` 改为 `empty`、`decoder`，分别验证空地址和无效音频提示；`ok` 返回 20 秒静音 WAV，验证正常播放；`slow` 延迟 10 秒，验证用户主动停止后不弹错误。
4. 再次打开搜索，应保留关键词、站点和类型，关键词全选。退出重开后也应保留。
5. 移动、重命名搜索列表以及将集合复制到另一普通列表后，回车仍应打开正确项目；混合列表中的普通歌曲保持默认播放行为。
6. 搜索窗口切换两个测试音源，站点应随之切换为 QQ 或咪咕。咪咕仅显示单曲类型；无搜索接口的测试汽水项不显示。菜单可打开管理音源及检查更新；管理中设置当前音源后，旧列表重播时使用新源。

自动化用例不替代实际宿主 UI 检查；发布前应在目标 foobar2000 版本上按上述步骤验证。
